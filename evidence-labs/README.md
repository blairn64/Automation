# Evidence Labs

These labs fill the gaps between technologies listed on my CV and what can safely be demonstrated in a public repository.

The labs are **standalone portfolio exercises**. They are not copies of employer environments and contain no client, tenant, production, credential, or proprietary data.

## Coverage

| Area | Evidence |
| --- | --- |
| NoSQL | MongoDB document model + Python client example |
| Power BI | Report-ready operational dataset + modelling notes |
| Wazuh | Wazuh architecture and rule-writing lab notes |
| Grafana | Dashboard JSON + Prometheus-style metrics example |
| Zabbix | Monitoring template/runbook example |
| Firewalls | Linux nftables policy example |
| VPN | WireGuard lab configuration pattern |
| DNS/DHCP | dnsmasq lab configuration and troubleshooting notes |
| Network segmentation | VLAN/subnet design example |

## Why these exist

The CV contains a mixture of current professional experience, older platform experience, and technologies used in production environments that cannot be reproduced publicly without exposing the original environment.

Where a safe public demonstration is possible, these labs provide one. Where a product requires a licensed or hosted environment, the repository documents the operating model rather than claiming that a fake implementation is the product itself.

## Safety

All addresses, hostnames, usernames, tenant IDs, subscriptions and credentials in examples are fictional. Replace them only inside a private lab.
